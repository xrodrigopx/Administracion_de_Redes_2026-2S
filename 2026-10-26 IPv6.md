## 1. Por qué IPv6 (lo mínimo)

- IPv4: 32 bits → 2^32 ≈ 4,3·10^9 direcciones, **agotadas** (IANA en 2011; los RIRs ya asignan su último /8). Se sobrevive con **direcciones privadas + NAT** (10/8, 172.16/12, 192.168/16), que rompe la conectividad extremo a extremo.
- IPv6: **128 bits** → 2^128 direcciones. Objetivo: direccionamiento público para todo dispositivo, **sin NAT**.
- Mejoras prácticas: encabezado fijo más simple, **autoconfiguración**, IPsec incluido (AH/ESP como extension headers), etiqueta de flujo para QoS, ND más eficiente que ARP.
- **DNS**: registro **A** → IPv4, **AAAA** → IPv6. Una aplicación que resuelve un AAAA usa IPv6. En una URL la dirección va entre corchetes: `https://[2800:3f0:4002:801::1010]`.

## 2. Encabezado IPv6

Tamaño **fijo de 40 bytes** (IPv4: 20 B + opciones variables).

| Campo | Bits | Comentario |
|---|---|---|
| Version | 4 | = 6 |
| Traffic Class | 8 | Equivale al TOS/DSCP de IPv4 → **QoS** |
| Flow Label | 20 | Identifica un flujo (mismos routers/tratamiento) |
| Payload Length | 16 | Largo de lo que sigue al encabezado de 40 B |
| Next Header | 8 | Qué viene después: TCP (6), UDP (17), **ICMPv6 (58)**, o una extension header |
| Hop Limit | 8 | Equivale al TTL |
| Source / Destination | 128 + 128 | |

- **Desaparecieron** respecto a IPv4: IHL, Identification/Flags/Fragment Offset, **Header Checksum** y Options. Menos trabajo por router.
- **Opciones → extension headers** encadenadas por Next Header: Hop-by-Hop (0), Routing (43), **Fragment (44)**, Destination Options (60), **ESP (50)** y **AH (51)** (cifrado y autenticación).
- **Fragmentación**: los routers **no fragmentan**. Solo lo hace el origen (header Fragment) tras descubrir el MTU del camino (**Path MTU Discovery**: el router descarta y responde ICMPv6 *Packet Too Big*). MTU mínimo de un enlace IPv6: **1280 B**.

## 3. Formato y notación de direcciones

- 128 bits = **8 grupos de 16 bits** en hexadecimal separados por `:` (cada grupo = 4 dígitos hex). Se usan **prefijos** (`/n`), no máscaras.
- **Reglas de compresión**:
  1. En cada grupo se pueden **omitir los ceros a la izquierda** (`0db8` → `db8`, `0000` → `0`).
  2. **Una sola vez** por dirección, una secuencia de grupos consecutivos todos en cero se reemplaza por `::`. Si hay dos secuencias, se comprime la **más larga** (si empatan, la primera). No se usa `::` para un único grupo en cero (por convención).
- **Expandir**: contar los grupos que se ven; `::` rellena con ceros hasta llegar a 8 grupos.

**Ejemplos**

| Completa | Comprimida |
|---|---|
| `2800:03f0:4002:0801:0000:0000:0000:1012` | `2800:3f0:4002:801::1012` |
| `2001:0db8:0000:0001:0000:0000:0000:0001` | `2001:db8:0:1::1` (se comprime la racha más larga, la de 3 grupos) |
| `fe80:0000:0000:0000:021d:09ff:fe3b:92af` | `fe80::21d:9ff:fe3b:92af` |

Expandir `2001:db8::5:0:1`: se ven 5 grupos (`2001`, `db8`, `5`, `0`, `1`) → `::` son 3 grupos → `2001:0db8:0000:0000:0000:0005:0000:0001`.

**Prefijo**: `2001:db8:a:b::/64` → los primeros 64 bits (4 grupos) identifican la red. Con prefijos múltiplo de 16 se lee directo por grupos; con otros (ej. /12, /52) hay que mirar en binario el dígito hex donde cae el corte (cada dígito hex = 4 bits).

## 4. Tipos de direcciones y prefijos

| Tipo | Prefijo | Aspecto | Notas |
|---|---|---|---|
| **Loopback** | `::1/128` | `::1` | Equivale a 127.0.0.1 |
| **No especificada** | `::/128` | `::` | Origen mientras el host aún no tiene dirección (ej. DAD) |
| **Unicast global (GUA)** | `2000::/3` | empieza con `2` o `3` | Ruteable en Internet. LACNIC: `2800::/12` |
| **Link-local** | `fe80::/10` | `fe80`–`febf` | **Solo en el enlace**, nunca se rutea. La tiene toda interfaz IPv6; la usa NDP |
| **ULA** (Unique Local) | `fc00::/7` (en la práctica `fd00::/8`) | `fd..` | Equivale a las privadas de IPv4, **sin NAT**; no se rutea en Internet |
| **Multicast** | `ff00::/8` | `ff..` | No existe broadcast en IPv6 |
| **Documentación** | `2001:db8::/32` | `2001:db8:...` | Solo para ejemplos |
| **6to4** | `2002::/16` | `2002:...` | Transición (ver §10) |
| **Teredo** | `2001::/32` | `2001:0:...` | Transición (ver §10) |

- **Anycast**: misma dirección unicast configurada en varios nodos; el paquete llega al más cercano. No tiene prefijo propio.
- **No hay broadcast**: lo reemplaza multicast (ej. `ff02::1` = todos los nodos del enlace).
- Una interfaz tiene **varias direcciones a la vez** (link-local + global + multicast…).
- **Alcance de multicast**: `ff0X::` — el dígito X es el scope. `ff02::` = **link-local** (no cruza routers).

**Identificar el tipo (rápido)**: mirar el primer grupo → `2xxx/3xxx` global · `fe8x–febx` link-local · `fcxx/fdxx` ULA · `ffxx` multicast · `::1` loopback.

## 5. Unicast global: estructura y subnetting

```
|  3 |      45 bits         |  16 bits  |         64 bits          |
|001 | global routing prefix| subnet ID |       interface ID       |
|<------------------ /48 --------------->|<-------- /64 ---------->
```

- **Interface ID: siempre 64 bits** → la subred estándar es **/64** (SLAAC lo exige).
- **Asignaciones típicas**:
  - IANA → **RIRs**: hasta /12.
  - RIR → **ISP**: **/32**.
  - ISP → **empresa/cliente final**: **/48** (65 536 subredes /64).
  - Residencial: **/64** (una subred) o, recomendado, **/56** (256 subredes).
- **Cuentas útiles** (cada bit de prefijo que se agrega duplica la cantidad de subredes):
  - /48 → /64: 64−48 = 16 bits → **2^16 = 65 536 subredes**.
  - /56 → /64: 8 bits → **256 subredes**.
  - /32 → /48: 16 bits → **65 536 clientes /48** por ISP.
  - Un /64 tiene **2^64 hosts** → nunca se "ahorra" direccionamiento dentro de una LAN.

**Ejemplo (subnetting).** Empresa con `2001:db8:abcd::/48`. Las subredes /64 se numeran con el 4.º grupo (el *subnet ID*):

- Subred 0: `2001:db8:abcd:0::/64`
- Subred 1: `2001:db8:abcd:1::/64`
- Subred 10 (decimal): `2001:db8:abcd:a::/64`
- Subred 255: `2001:db8:abcd:ff::/64`; subred 256: `2001:db8:abcd:100::/64`

Es **hexadecimal**: después de `9` viene `a`, después de `ff` viene `100`.

Para dividir en bloques /56 (uno por sucursal): el subnet ID se escribe con 2 dígitos hex de "sucursal" + 2 de "subred": `2001:db8:abcd:0100::/56` es la sucursal 1, `...:0200::/56` la 2, etc.

## 6. Interface ID: EUI-64

Forma el ID de interfaz de 64 bits a partir de la **MAC de 48 bits** (la usa SLAAC, y para generar la link-local `fe80::IID`).

**Procedimiento**
1. Partir la MAC por la mitad (3 + 3 octetos).
2. Insertar **`FF FE`** en el medio → 8 octetos.
3. **Invertir el bit U/L** = 7.º bit del primer octeto (el segundo menos significativo): equivale a **sumar/restar `0x02`** al primer octeto (`00`→`02`, `02`→`00`, `3c`→`3e`).

**Ejemplo.** MAC `00:12:7F:EB:6B:40`
- Insertar FFFE: `00:12:7F:FF:FE:EB:6B:40`
- Invertir U/L (primer octeto `00` = `0000 0000` → `0000 0010` = `02`): `02:12:7F:FF:FE:EB:6B:40`
- IID = `0212:7fff:feeb:6b40` → link-local **`fe80::212:7fff:feeb:6b40`**
- Con prefijo `2001:db8:1:1::/64` → global **`2001:db8:1:1:212:7fff:feeb:6b40`**

**Reconocer una EUI-64**: en el medio del IID aparece `ff:fe` (`...:XXff:feXX:...`). Para volver a la MAC: sacar `fffe` y re-invertir el bit.

**Privacidad**: EUI-64 expone la MAC y permite rastrear al host → los sistemas usan **IID aleatorios** (privacy extensions, RFC 3041/4941): `prefijo /64 + 64 bits aleatorios`.

## 7. Multicast y Solicited-Node

Direcciones multicast importantes (todas link-local, `ff02::`):

| Dirección | Grupo |
|---|---|
| `ff02::1` | **Todos los nodos** (reemplaza al broadcast) |
| `ff02::2` | **Todos los routers** |
| `ff02::1:ffXX:XXXX` | **Solicited-Node** (ver abajo) |
| `ff02::9` | Todos los routers RIPng |
| `ff02::1:2` | Servidores/relays DHCPv6 |

**Solicited-Node**: por **cada dirección unicast/anycast** que tiene, un nodo se une al grupo `ff02::1:ff` + **últimos 24 bits** (6 dígitos hex) de esa dirección. Es lo que usa NDP para resolver direcciones: solo "molesta" al puñado de nodos cuyos últimos 24 bits coinciden (a diferencia del broadcast ARP, que interrumpe a todos).

**MAC de una dirección multicast IPv6**: `33:33` + **últimos 32 bits** (4 octetos) de la dirección IPv6.

**Ejemplo.** B = `2001:db8:a739:4e38:201:6cff:fe70:991c`
- Últimos 24 bits: `70:991c` → Solicited-Node = **`ff02::1:ff70:991c`**
- MAC multicast de destino = `33:33` + `ff:70:99:1c` = **`33:33:ff:70:99:1c`**
- Su propia MAC `00:01:6c:70:99:1c` se confirma por EUI-64: `00`→`02`, `fffe` en el medio → `0201:6cff:fe70:991c` ✓.

## 8. ICMPv6 y Neighbor Discovery (NDP)

- **ICMPv6** (Next Header **58**) es obligatorio e hace de "súper protocolo": errores y diagnóstico (como ICMPv4, ej. *Packet Too Big* para PMTUD), **NDP** y **MLD** (gestión de grupos multicast, equivale a IGMP).
- **NDP** (Neighbor Discovery) reemplaza a **ARP + ICMP Router Discovery + ICMP Redirect** (y habilita autoconfiguración). Se manda por multicast en el enlace (y con **Hop Limit = 255**, para garantizar que el origen está en el mismo enlace).
- Funciones: descubrir routers y prefijos, descubrir parámetros (MTU, hop limit), **autoconfiguración**, **resolución de direcciones** (IP→MAC), determinar next hop, detectar vecino inalcanzable (**NUD**), **detectar direcciones duplicadas (DAD)**, redirección.

### Los 5 mensajes (tipos ICMPv6)

| Tipo | Mensaje | Quién lo envía / para qué | Destino típico |
|---|---|---|---|
| **133** | **Router Solicitation (RS)** | Host: pide un RA ya, sin esperar al periódico | `ff02::2` (todos los routers) |
| **134** | **Router Advertisement (RA)** | Router: periódico o en respuesta a RS. Trae **prefijo(s)**, flags, MTU, hop limit, tiempos de vida | `ff02::1` (todos los nodos) o unicast al que hizo RS |
| **135** | **Neighbor Solicitation (NS)** | Resolver la MAC de un vecino, verificar que sigue alcanzable (NUD) o **DAD** | Solicited-Node del *target* (o unicast para NUD) |
| **136** | **Neighbor Advertisement (NA)** | Respuesta al NS (con la MAC del target) o aviso de cambio de MAC | Unicast al que preguntó (o `ff02::1`) |
| **137** | **Redirect** | Router: "para ese destino hay un mejor first hop" | Unicast al host |

### Resolución de direcciones (el "ARP" de IPv6)

A (`IPv6_A`, `MAC_A`) quiere hablar con B y conoce solo `IPv6_B`:

1. A calcula el Solicited-Node de B (`ff02::1:ffXX:XXXX`, últimos 24 bits de `IPv6_B`) y envía un **NS**:
   - L3: origen `IPv6_A`, destino `ff02::1:ffXX:XXXX`
   - L2: origen `MAC_A`, destino `33:33:ffXX:XXXX` (multicast)
   - Opción ICMPv6: *Source Link-Layer Address* = `MAC_A`
2. B (que pertenece a ese grupo) responde un **NA** **unicast** a A con la opción *Target Link-Layer Address* = `MAC_B`.
3. A guarda la entrada IP↔MAC en su **neighbor cache** (equivalente a la tabla ARP; se ve con `show ipv6 neighbors` / `ip -6 neigh`).

Si A y B no están en el mismo enlace, A resuelve la MAC de su **router por defecto**, no la de B.

### DAD (Duplicate Address Detection)

Antes de usar cualquier unicast (link-local o global), el host envía un **NS con origen `::`** y destino el Solicited-Node de **la dirección que quiere usar** (*tentative*). Si **alguien contesta con un NA**, la dirección está duplicada y **no se configura**. Sin respuesta → se usa.

## 9. Autoconfiguración: SLAAC y DHCPv6

### SLAAC (Stateless, sin servidor)

Pasos al conectar un host a una LAN con router IPv6:

1. Genera su **link-local**: `fe80::` + IID (EUI-64 o aleatorio).
2. Hace **DAD** de esa link-local; si es única, la configura.
3. Envía un **RS** a `ff02::2` (así no espera al RA periódico).
4. El router responde con un **RA** que incluye el **prefijo /64** (con flag **A** = autonomous), MTU, hop limit, lifetimes y los flags **M** y **O**.
5. El host forma la dirección global = **prefijo del RA + IID** y hace DAD de ella.
6. Como gateway por defecto usa la **link-local del router** (la dirección origen del RA).

- **Si no hay RA** (router no configurado): el host solo tiene link-local → solo comunica en el enlace.
- **Prefijo de SLAAC debe ser /64** (porque el IID es de 64 bits).
- Los RA también pueden traer DNS (opciones **RDNSS / DNSSL**).

### DHCPv6 (Stateful) y flags del RA

| Flags en el RA | Dirección | Otros datos (DNS, dominio…) |
|---|---|---|
| M=0, O=0 | **SLAAC** | Ninguno / manual (o RDNSS en el RA) |
| M=0, **O=1** | **SLAAC** | **DHCPv6 *stateless*** (solo parámetros) |
| **M=1** | **DHCPv6 *stateful*** (el servidor asigna y lleva registro) | DHCPv6 |

- **M** = Managed address configuration; **O** = Other configuration.
- Secuencia stateful: RS → RA (con M=1) → DHCPv6 *Solicit/Advertise/Request/Reply* (UDP: cliente 546, servidor 547; multicast `ff02::1:2`).
- **Importante**: DHCPv6 **no entrega el gateway por defecto**; el gateway siempre viene del **RA**.
- Resumen de formas de configurar una dirección: **manual**, **DHCPv6**, **SLAAC con EUI-64** (`/64 + EUI-64`), **SLAAC con IID aleatorio** (`/64 + 64 bits random`).

## 10. Transición a IPv6

| Mecanismo | Idea | Datos a recordar |
|---|---|---|
| **Dual stack** | El nodo corre IPv4 e IPv6 a la vez | La opción preferida: no requiere traducción |
| **6in4** | Túnel **manual** punto a punto: paquete IPv6 encapsulado en IPv4 | **Protocolo IP 41** |
| **6to4** | Túnel automático; el prefijo se arma con la IPv4 pública | Prefijo **`2002:<IPv4 en hex>::/48`**, protocolo 41 |
| **Teredo** | IPv6 sobre **UDP/IPv4**, atraviesa NATs | **`2001:0::/32`** |
| **6rd** | Como 6to4 pero con el prefijo del proveedor | `prefijo del ISP (ej. /32) + IPv4 + ...`, protocolo 41 |

**Ejemplo 6to4.** Router con IPv4 pública `200.40.0.85`: 200 = `c8`, 40 = `28`, 0 = `00`, 85 = `55` → `c828:0055` → prefijo **`2002:c828:55::/48`** (quedan 16 bits de subnet ID → 65 536 /64).

- En todos los túneles, el **MTU efectivo baja** (se agrega un encabezado IPv4 de 20 B).
- **Aplicaciones**: si el DNS devuelve AAAA y el host tiene IPv6, usan IPv6; si no, caen a A (IPv4).

5. Una empresa recibe `2001:db8:abcd::/48`. (a) ¿Cuántas subredes /64 puede crear? (b) ¿Cuál es la subred /64 número 42 (decimal, empezando en 0)? (c) Si se divide en sucursales con bloques /56, ¿cuántos bloques /56 hay y qué prefijo tiene el tercero (empezando en 0)?

8. Un host se conecta a una red; el RA trae M=0, O=1 y prefijo `2001:db8:5:5::/64`. Detallá los pasos que hace el host hasta tener conectividad total (dirección, gateway, DNS).
9. Un host recibe un RA con M=1. ¿Qué cambia? ¿De dónde obtiene el gateway?
10. Un cliente con IPv4 público `192.0.2.4` quiere usar 6to4. ¿Qué prefijo le corresponde?
11. IPv6 eliminó el checksum de cabecera y la fragmentación en los routers. ¿Cómo se maneja entonces un paquete más grande que el MTU del enlace?
12. Dos hosts en la misma LAN, sin router IPv6 ni DHCPv6. ¿Pueden comunicarse? ¿Con qué direcciones?
13. Un administrador ve que la tabla de vecinos de su host muestra la MAC del router pero no la de un servidor en otra red. ¿Es un problema? ¿Por qué?
14. Diferenciá en una frase: link-local, ULA y global. ¿Cuáles se rutean en Internet?
